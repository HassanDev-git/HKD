# HKD Compatibility Guarantees & SemVer Contract

## 1. Semantic Versioning (SemVer 2.0.0)
HKD strictly adheres to Semantic Versioning (`MAJOR.MINOR.PATCH`):
- **MAJOR (1.x.x)**: Breaking changes to syntax, frozen error codes, bytecode serialization format, or native ABI require bumping MAJOR to `2.0.0`.
- **MINOR (x.1.x)**: Backwards-compatible language additions, new standard library functions, or compiler optimizations.
- **PATCH (x.x.1)**: Backwards-compatible bug fixes and security hardening.

---

## 2. Backward Compatibility Promise
Starting with **HKD 1.0.0**, any syntactically valid program targeting `Edition 2026` will continue to compile and produce identical runtime behavior on any future `1.x.y` release.

---

## 3. Bytecode Compatibility Policy
- Bytecode files (`.hkdb`) compiled with HKD `1.x.y` will execute on any subsequent `1.x.z` runtime where $z \ge y$.
- Runtimes will explicitly reject bytecode with major version mismatches or unknown opcode indices with a descriptive diagnostic message, preventing silent execution of incompatible binary chunks.

---

## 4. Package Ecosystem Compatibility
- Lockfile V2 (`hkd.lock`) will remain compatible across all `1.x.y` compiler versions.
- `.hkdpack` archives generated by HKD 1.0.0 will be decipherable by all future 1.x releases.
